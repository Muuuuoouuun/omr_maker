# 오답 보강 관리

이번 범위는 **오답 배정 → 수정 결과 → 교사 확인** 한 흐름이다. 교사는 학생과 기한만 선택하며, 시스템이 최신 제출·미완료·담당 변화를 구분한다. 유사 문제 생성, 자동 메시지 발송, 새 요금제는 포함하지 않는다.

## 사용

- 교사 계정 메뉴 → 오답 보강 관리 (`/teacher/remediation`). 서버에 정식 채점 결과가 있는 등록 학생의 미배정 원시험 중 최근 50건이 후보가 된다.
- 원시험의 오답·미응답 전체를 한 건으로 배정한다. 한 번에 20건, 한국 시간 23:59 마감, 최대 90일. 배정자가 담당 교사다.
- 학생 학습 홈 → 선생님이 배정한 오답 보강 (`/student/remediation`) → 기존 원시험 리뷰와 다시 풀기. 이 목록은 **시험 공개·개별 재시험 배정 권한을 새로 부여하지 않는다**. 시험이 닫혔거나 배정이 바뀐 경우 기존 시험 배포/재시험 배정을 먼저 확인한다.
- 같은 문제를 다시 맞히면 ‘교사 확인 필요’. 별도 문항 풀이 또는 설명을 확인하고 근거를 5자 이상 기록해야 ‘교사 확인 완료’로 처리한다. 정답 수정은 독립적인 유형 숙달의 증거로 간주하지 않는다.

## 시스템 규칙

| 영역 | 적용 규칙 |
| --- | --- |
| 권한 | 서명 세션 + 현재 DB 회원 상태·역할 + 조직 + 담당 반 + 작업 종류를 검증한다. 원장/관리자는 조직 내, 교사는 lead/co_teacher 반만 수정한다. grader는 담당 반 조회만, assistant는 담당 반 조회만 가능하다. viewer는 접근하지 못한다. |
| 근거 | 원시험과 같은 학생·조직·시험·원문항 정의의 서버 채점 재시험만 사용한다. 문항별 가장 최근 결과를 선택하여 과거 정답으로 새 오답을 가리지 않는다. |
| 완료 | 완료 시 사용한 근거 키를 보존한다. 새 제출로 근거가 바뀌면 재오답 점검 또는 교사 확인 필요로 다시 표시한다. 자동으로 ‘숙달’ 처리하지 않는다. |
| 예외 | 재오답, 기한 초과, 교사 확인 순으로 우선 표시한다. 반 이동·휴원·담당 권한 상실은 ‘담당·재원 확인 필요’로 표시하며 자동 완료하지 않는다. 사유를 남겨 보류하고 재개할 수 있다. |
| 동시 수정 | revision과 제출 근거 키를 모두 비교한다. 배정은 원시험당 한 건으로 중복 클릭을 흡수하며, 섞인 권한의 일괄 배정은 전체 취소된다. |
| 요금제 | 배정·확인·보류·재개는 현재 Pro/Academy 권한이 필요하다. 만료 후 기존 기록 조회는 유지한다. |
| 감사·개인정보 | 배정·완료·보류·재개를 기존 감사 로그에 기록한다. 학생 응답에는 교사 내부 메모, 다른 학생 정보, 정답 키가 없다. |

교사 목록은 우선순위 정렬 후 50건씩 페이지를 나눈다. 학생 목록은 최대 50건이다. 새 교사 초대/역할 편집 UI와 다른 교사 화면의 권한 일괄 전환, 담당자 재지정은 이번 범위가 아니다. 기존 계정 모델의 신규 가입 owner 경계를 그대로 유지한다.

## 배포와 검증

1. 정렬된 기존 마이그레이션 다음 `202609100002_remediation_management.sql`을 적용한다.
2. `production-server-boundary.sql`을 재적용한다. 새 테이블은 FORCE RLS, 브라우저 권한 없음, service_role도 조회만 가능하며 수정은 검증 RPC를 거친다. rollback 프로필도 이 제한을 유지한다.
3. `npm run test:supabase:live`는 격리 로컬 PostgreSQL에서 실제 채점 writer와 보강 SQL을 검증한다. 운영 DB나 알림 발송에는 연결하지 않는다.
4. 새 테이블은 canonical 백업 목록에 자동 포함된다. 마이그레이션 미적용·연결 오류는 빈 목록이 아니라 오류로 표시한다.

현재 화면은 입력을 단순하게 유지하기 위해 기간 변경·다중 담당·반 이동 인수인계·자동 알림을 제공하지 않는다. 다음 작업은 새 기능 확장보다 실제 학원의 ‘보강 배정 후 다시 풀기’ 운영 검증과 담당 변경 절차 보완이다.
