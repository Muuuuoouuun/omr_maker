# 분석·통계 리포트 디자인 디벨롭

작성일: 2026-08-08  
범위: 교사 대시보드 시험 분석·학생 성취도, 개별 학생 결과의 분석·리포트  
우선순위: 시각적 완성도 → 새 계산 지표·추천 → 정보 구조 정리  
기준 화면: 데스크톱 교사 화면. 태블릿·모바일은 동일한 정보 위계를 안전하게 축약한다.

## 1. 목표

분석 화면을 기능 목록이 아니라 교사가 읽고 판단하는 리포트로 만든다. 교사는 첫 화면에서 핵심 변화와 다음 행동을 이해하고, 차트와 표에서 그 판단의 근거를 확인하며, 집단 분석에서 개별 학생 리포트까지 같은 시각 문법으로 이동할 수 있어야 한다.

완료 기준은 다음과 같다.

- 시험 분석 첫 화면에서 시험 범위, 핵심 지표, 가장 중요한 해석, 근거, 다음 행동이 순서대로 보인다.
- 개별 학생 리포트는 집단 화면과 같은 문법을 유지하되 비교·오답·추천 정보를 더 높은 밀도로 제공한다.
- 개인 성장 그래프에서 학생 추세, 반 평균, 평균 격차, 시험별 등수를 읽을 수 있다.
- 개인 성장 그래프는 `요약 / 추세만` 내부 탭으로 정보 밀도를 전환한다.
- 기존 답안·필기·리포트·분석 딥링크, 인쇄, 요금제 게이트, 분석 지연 로딩을 보존한다.
- 빈 데이터, 부분 데이터, 오래된 데이터, 오류 상태를 서로 다르게 표현한다.
- 그래프와 표는 데스크톱·태블릿·모바일·200% 확대에서 깨지거나 문서 전체 오버플로를 만들지 않는다.
- 정상 모션과 OS/app 감소 모션 모두에서 콘텐츠가 숨거나 늦게 나타나지 않는다.

## 2. 확정된 시각 방향

선택안은 **B형 리포트형**이다. 파란색과 흰색을 중심으로 한 기존 브랜드 톤을 유지하되, 카드 나열보다 큰 숫자, 문장형 해석, 절제된 구획선을 사용한다.

화면의 기본 읽기 순서는 다음과 같다.

1. 시험 또는 학생 컨텍스트
2. 큰 핵심 지표
3. 지금 가장 중요한 해석 한 문장
4. 차트·표·문항 목록 같은 판단 근거
5. 보강, 재시험, 학생 확인 같은 다음 행동

교사 대시보드 시험 분석은 집단의 변화와 취약 개념을 강조한다. 학생 성취도와 개별 학생 결과는 개인 성장, 반 평균 격차, 반복 오답, 추천 학습을 강조한다. 개별 리포트는 교사가 특정 학생을 조사하러 들어온 화면이므로 시험 리포트보다 약 1.5배 높은 정보 밀도를 허용한다.

## 3. 정보 구조

### 3.1 교사 대시보드 시험 분석

기존 상위 `대시보드 요약 / 시험 분석 / 학생 성취도`와 시험 분석 내부 `요약 / 문항 분석 / 학생·반 / 운영` 구조를 유지한다. 기존 URL과 지연 로딩 계약을 깨지 않는 것이 우선이다.

시험 분석 `요약`은 다음 순서로 재구성한다.

- 시험명 검색, 지역 필터, 날짜, 문항 수, 제출 수
- 평균, 중앙값, 최고, 최저, 응시 수, 평균 풀이 시간 중 화면 폭에 맞는 핵심 지표
- 기존 계산값을 사용한 한 문장 핵심 해석
- 점수 분포와 성취 구간
- 취약 문항과 개념 근거
- 오늘의 수업 행동과 재시험·보강 연결

부모 대시보드의 데이터 건강 상태와 복구 행동은 시험 리포트보다 앞에서 경쟁하지 않는다. 시험 탭에서는 리포트의 상태/행동 영역으로 합치거나, 시스템 복구가 필요한 경우에만 축약 배너로 남긴다.

`문항 분석`, `학생·반`, `운영`의 기능은 삭제하지 않는다. 다만 각 뷰를 독립 컴포넌트로 분리하고 리포트 섹션 문법을 공유한다.

### 3.2 학생 성취도와 개별 결과 연결

집단 리포트의 취약 학생 행이나 학생 성취도 목록에서 개별 결과로 이동할 때 선택한 학생과 분석 문맥을 유지한다. 개별 결과의 기존 `답안 / 필기 / 리포트 / 분석` 딥링크는 유지한다.

개인 성장 UI는 `리포트`의 누적 성장 섹션에 배치하고 `분석`에 중복 노출된 누적 성장 블록은 제거한다. `분석`은 현재 시험의 오답·행동·추천에 집중하고, `리포트`는 누적 추세와 비교를 담당한다.

### 3.3 개인 리포트 밀도

개인 리포트는 한 데스크톱 뷰에서 다음을 함께 보여준다.

- 최근 점수, 반 백분위, 성장 추세, 반복 약점, 평균 풀이 시간
- 반복 약점을 설명하는 문장형 핵심 해석
- 개인 성장 흐름
- 반복 오답 패턴
- 추천 학습 순서
- 이번 시험 응답 요약
- 시험별 근거와 상세 분석 표

모든 정보를 같은 강도로 보이지 않는다. 문장형 핵심 해석과 최근 점수를 가장 강하게, 비교와 근거는 중간 강도로, 상세 표는 탐색용 밀도로 배치한다.

## 4. 개인 성장 그래프

### 4.1 표시 데이터

각 시험 행은 다음 값을 가진다.

- 학생 점수
- 동일 반 학생의 평균 점수
- `학생 점수 - 반 평균` 격차
- 반 내 등수와 참가자 수
- 시험명과 날짜
- 최신 시험 여부

학생 점수는 브랜드 파란 실선, 반 평균은 중립색 점선으로 표시한다. 점수 라벨은 학생 선 가까이에, 평균 격차는 두 선 사이의 작은 배지로 표시한다. 등수는 X축 아래 보조 행에 `18위 / 32명`처럼 표시하고 최신 시험은 등수 변화까지 `18위 ↑5`로 강조한다.

### 4.2 내부 탭

`요약`은 기본 상태다. 그래프 오른쪽에 최근 점수, 최근 6개 평균 격차, 현재 등수, 직전 시험 대비 등수 변화, 최근 추세를 보여주는 요약 레일을 배치한다.

`추세만`은 요약 레일을 접고 그래프가 가용 폭 전체로 확장된다. 탭은 roving focus, Arrow keys, Home/End, Enter/Space를 지원하며 선택 탭과 패널의 ARIA 관계를 가진다.

### 4.3 크기와 오버플로

- 차트 프레임은 `min-width: 0`과 안정적인 높이를 가진다.
- 데스크톱에서는 최근 6~8개 시험이 한 번에 보인다.
- 좁은 화면에서 SVG를 찌그러뜨리지 않는다. 필요한 최소 폭을 보존하고 차트 영역 안에서만 가로 스크롤한다.
- 스크롤 영역에는 이름, 키보드 포커스, 보이는 이동 안내와 우측 페이드 단서를 제공한다.
- 페이지 자체에는 가로 스크롤이 생기지 않는다.
- 긴 한글 시험명은 축 라벨에서 축약하고 전체 이름은 접근 가능한 데이터 표와 툴팁에서 제공한다.

### 4.4 모션

정상 모션은 평균선과 학생선 그리기, 포인트 순차 등장, 평균 격차 배지 등장, 최신 시험의 약한 펄스 순서로 실행한다. 모션은 정보를 가리지 않으며 한 번의 화면 진입에만 실행한다.

Recharts 내장 애니메이션과 별도 DOM 애니메이션을 중복 사용하지 않는다. 하나의 컨트롤러가 모션을 소유하며 기존 `useCometReveal`의 감소 모션 패턴을 따른다.

다음 조건에서는 최종 정적 상태를 즉시 표시한다.

- OS `prefers-reduced-motion: reduce`
- 앱 `html[data-motion="off"]`
- 인쇄
- 숨겨진 탭에서 복귀한 재마운트

## 5. 계산과 데이터 정책

### 5.1 시험 리포트 모델

`buildExamAnalyticsReportModel(...)` 같은 순수 모델 빌더가 기존 계산값을 리포트용 뷰 모델로 투영한다. 첫 구현은 백엔드 변경 없이 다음 값을 사용한다.

- 평균, 중앙값, 최고, 최저, 응시 수, 평균 풀이 시간, 표준편차
- 점수 분포와 성취 구간
- 가장 취약한 개념
- 위험 문항, 지나치게 쉬운 문항, 변별력이 낮은 문항 수
- 60점 미만, 60~79점, 90점 이상 학생 수
- 문항별 정·오답·미응답률, 대표 오답, 변별도, 풀이 시간, 재방문, 답 변경
- 반별 평균·최저·중앙값·최고, 참여·미응시, 행동 신호

한 문장 해석은 결정적 규칙으로 만든다. 같은 입력은 항상 같은 문장을 만들며, 작은 표본이나 불완전한 문항 결과에서는 확정적인 추천 대신 관찰 문구를 사용한다.

### 5.2 학생 성장 리포트 모델

새 순수 모듈 `studentGrowthReport`가 선택 학생, 전체 조직 제출, 시험, 명단·그룹을 입력받아 시간순 성장 행과 요약 값을 만든다.

계산 정책은 다음과 같다.

- 원시험 제출만 성장 추세와 반 평균에 사용한다.
- 동일 학생의 같은 시험 원시험 제출이 여러 개면 현재 제품의 시리즈 식별 정책에 따라 대표 제출 한 개를 사용한다.
- 반은 안정적인 명단·그룹 ID로 구분하고, 이름이 같은 반이나 지역이 섞이지 않게 한다.
- 등수 동점은 동일 점수를 동일 등수로 처리하는 기존 `computeRankPercentile` 정책과 일치시킨다.
- 참가자가 1명뿐이면 평균은 표시할 수 있지만 등수 비교 문장은 숨긴다.
- 시험 또는 학생 식별이 불완전하면 해당 행을 제외하고 상태 설명에 누락 건수를 포함한다.
- 개인 이력은 오래된 시험부터 최신 시험 순으로 정렬한다.
- 표시 반올림은 뷰 모델에서 한 번만 수행한다.

현재 개별 결과의 누적 로드는 선택 학생 제출만 남기고 반 친구 제출을 버린다. 새 모델을 위해 전체 제출과 그룹 정보를 유지하되, 렌더 컴포넌트에는 계산이 끝난 작은 뷰 모델만 전달한다.

### 5.3 부분 데이터

원격 부분 응답, 오래된 캐시, 문항 결과 누락을 `ready`와 동일하게 취급하지 않는다. 보고서 상태는 다음의 판별 가능한 상태를 사용한다.

- `loading`
- `error`
- `empty`
- `stale`
- `partial`
- `ready`

`stale`과 `partial`은 사용 가능한 데이터를 보여주되 평균과 등수 옆에 상태 설명을 표시한다. `error`는 시스템 오류색과 재시도 행동을, 오답과 낮은 정답률은 채점 전용 `--grade-red`를 사용한다.

## 6. 컴포넌트 경계

도메인 계산은 공유하지 않고, 리포트 표현 문법만 공유한다.

공통 표현 컴포넌트:

- `AnalyticsReportSection`: 제목, 설명, 메타, 행동, 밀도, 인쇄 분할 규칙을 가진 의미 있는 섹션
- `AnalyticsMetricGrid` / `AnalyticsMetric`: 숫자 폰트, 단위, 추세, 톤, 카운트업을 통일
- `AnalyticsChartFrame`: 안정적 크기, 로딩·빈·오류 상태, 텍스트 요약, 접근 가능한 표, 오버플로와 모션 정책
- `ReportStateBoundary`: loading/error/empty/stale/partial/ready 상태 전환

시험 분석 분리:

- `ExamAnalyticsContextHeader`
- `ExamAnalyticsReportOverview`
- `ExamMetricSummary`
- `ExamHeadlineInsight`
- `ScoreDistributionEvidence`
- `WeakQuestionsEvidence`
- `AchievementBandsEvidence`
- `ExamNextActions`
- `ExamOperationsView`
- `ExamQuestionEvidenceView`
- `ExamCohortEvidenceView`

개인 리포트 분리:

- `StudentGrowthReport`
- `GrowthSummaryRail`
- `GrowthTrendChart`
- `studentGrowthReport` 순수 계산 모듈

초기 분리에서는 계산을 기존 부모에 유지하고 화면 블록만 추출한다. 동작이 고정된 뒤 순수 모델 빌더로 옮긴다. 시험 분석의 운영 로컬 저장·카카오 상태는 `ExamOperationsView` 안에 함께 둬 생명주기를 보존한다.

새 컴포넌트는 프로젝트 관행에 따라 `src/components/` 또는 기존 도메인 폴더에 둔다. 새로운 범용 `ui/` 폴더를 만들지 않는다.

## 7. 디자인 시스템과 접근성

- 한글은 Pretendard 상속을 사용한다.
- 핵심 숫자는 `.numeric-emphasis`와 Geist 숫자 스타일을 사용한다.
- 한글 제목에 강한 음수 자간을 사용하지 않는다.
- `--error`는 시스템 실패, `--grade-red`는 오답·정답률에만 사용한다.
- 성공·주의·오류 상태의 작은 텍스트는 기본 상태색이 아니라 대비가 확보된 `--text-success`, `--text-warning`, `--text-error`를 사용한다.
- 상태 배지는 `StatusPill`을 재사용하고 톤 타입을 공개해 인라인 색 조합을 줄인다.
- 차트는 SVG만으로 정보를 전달하지 않는다. 시험, 학생 점수, 반 평균, 격차, 등수를 담은 의미 있는 표 또는 목록을 함께 제공한다.
- 탭, 콤보박스, 정렬 헤더는 키보드로 조작 가능해야 한다.
- 가로 스크롤 표와 차트는 이름 있는 포커스 영역과 스크롤 안내를 가진다.
- 터치 컨트롤은 최소 44px 목표를 유지한다.
- 리포트 인쇄 루트와 강제 라이트 팔레트를 보존하고, 차트 데이터 표를 인쇄 대체물로 사용한다.

## 8. 상태와 오류 처리

- 시험이나 제출이 없으면 설정 행동이 포함된 빈 상태를 표시한다.
- 한 점만 있으면 추세선 대신 단일 시험 값과 비교 가능 범위를 설명한다.
- 반 비교 데이터가 없으면 개인 추세만 표시하고 평균·등수 영역은 이유와 함께 숨긴다.
- 부분 데이터에서는 숫자를 감추지 않되 `일부 제출 기준`을 지표와 문장에 명시한다.
- 필터 변경으로 기존 선택이 무효가 되면 가장 가까운 유효 선택으로 이동하고 이를 상태 문구로 알린다.
- 로드 오류는 리포트 전체를 빈 화면으로 만들지 않는다. 사용할 수 있는 이전 데이터가 있으면 stale 상태로 유지하고 재시도를 제공한다.
- 요금제 잠금은 기존 계산과 노출 정책을 보존한다. 잠긴 계산은 불필요하게 실행하지 않는다.

## 9. 테스트 전략

구현은 테스트 주도 순서로 진행한다.

### 9.1 순수 단위 테스트

- 시험 리포트 지표 순서와 핵심 해석 임계값
- 빈 데이터, 작은 표본, 부분 문항 결과 문구
- 학생 성장 반 격리, 동명 반, 지역, 안정적인 학생 ID
- 원시험만 포함, 재시험 제외, 중복 원시험 대표 선택
- 동점 등수, 1인 반, 시험 누락, 오래된 순 정렬, 반올림
- partial/stale/ready 상태 전파

### 9.2 컴포넌트 테스트

현재 Vitest는 node 환경이고 Testing Library/jsdom이 없다. 공통 프리미티브 추출 전에 DOM 컴포넌트 테스트 하네스를 추가한다.

- 섹션 제목과 `aria-labelledby`
- 지표 라벨·값·단위·추세·톤
- `요약 / 추세만` 탭의 roving focus와 키보드 활성화
- 0개, 1개, 다수 데이터의 차트 프레임
- 접근 가능한 차트 요약과 데이터 표
- OS/app 감소 모션에서 즉시 최종 상태
- 탭·학생·시험 변경 시 애니메이션 정리와 불필요한 재실행 방지
- 로딩 `role=status`, 오류 `role=alert`, 재시도

### 9.3 브라우저와 시각 회귀

- 1440×900: 시험 요약·문항·학생·운영, 개인 리포트·분석, 라이트·다크
- 1024×768: 2열에서 1열 전환과 지표 래핑
- 760px, 520px, 390px, 320px: 문서 오버플로와 차트 내부 스크롤
- 200% 확대, 긴 한글 시험명, 1개와 8개 데이터, 100개 이상 표 행
- 정상 모션, OS 감소 모션, 앱 모션 끄기
- 인쇄 미디어 리포트
- Chromium과 WebKit
- 집단 분석에서 선택 학생 리포트 이동, 브라우저 뒤로가기, 선택 복원

기존 성능 계약을 유지한다.

- 시험·학생 분석은 동적 import를 유지한다.
- 기본 대시보드 진입에서 Recharts와 대형 분석 모듈을 eager load하지 않는다.
- 뷰 모델 계산은 안정된 입력에서만 재실행한다.
- 차트 모션은 화면 진입마다 반복 재생되지 않는다.

## 10. 구현 순서

1. 순수 성장 계산과 시험 리포트 해석 테스트를 실패 상태로 작성한다.
2. 공통 리포트 프리미티브의 DOM 테스트 하네스와 실패 테스트를 작성한다.
3. 기존 딥링크·인쇄·동적 import 계약을 고정한다.
4. 시험 분석 요약을 리포트 순서로 추출·재배치한다.
5. 개인 리포트의 중복 누적 블록을 정리하고 고밀도 레이아웃을 적용한다.
6. 개인 성장 모델과 `요약 / 추세만` 그래프를 구현한다.
7. 접근성, 부분 데이터, 감소 모션, 인쇄를 보강한다.
8. 데스크톱부터 시각 회귀를 맞추고 태블릿·모바일을 검증한다.
9. 전체 단위·E2E·빌드·성능 계약을 통과시킨다.
