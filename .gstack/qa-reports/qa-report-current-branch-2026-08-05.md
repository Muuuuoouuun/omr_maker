## 결론

이전 production 탐색 QA에서 신뢰를 깨뜨렸던 배포 대상 인원 불일치, 구형 필기 미표시, 잘못된 강사 로그인 무응답, 저장 당시 플랜 의미 혼란, 좁은 화면 접근성 문제를 현재 브랜치에서 수정하고 회귀 테스트로 고정했다. 시험 생성 화면의 런타임 크래시, 계정/PDF 메뉴의 키보드 포커스 유실, 375px 설치 버튼의 접근성 이름 누락도 이번 단계별 검증에서 추가로 발견해 수정했다.

현재 자동화 범위 안에서 학생·강사 핵심 여정은 모두 통과한다. 강사 대시보드의 원격 동기화 실패도 로컬 캐시를 빈 배열로 덮지 않고 복구하며, 변이 E2E는 localhost가 아니면 명시적 opt-in 없이 실행되지 않는다. 다만 실제 외부 알림 발송, 실제 결제, 일반 교사 셀프 회원가입, 두 실물 기기 사이의 동시 진행/충돌은 아직 출시 완료 기능으로 볼 수 없다.

## 출시 전에 남은 게이트

다음은 이번 자동화가 통과했다고 주장하지 않는 항목이다.

1. 실제 Android Chrome과 iOS Safari에서 설치→standalone 실행→업데이트→오프라인 재실행.
2. 서로 다른 두 물리 기기에서 같은 계정의 동시 시험 진행, handoff, 충돌 해결.
3. Kakao/Web Push의 권한 요청, OS 수신, 백그라운드 수신, 클릭 딥링크.
4. 카드 결제, 구독 변경, 환불, webhook 재처리.
5. 일반 교사 셀프 회원가입·이메일 복구·계정 폐쇄 정책.
6. production fixture를 재현 가능한 상태로 초기화하고 실제 배포 환경에서 동일 120개 회귀 재검증.

## 출시 판정

현재 브랜치의 로컬 자동화 범위는 **READY_WITH_EXTERNAL_GATES**다. 핵심 학생·강사 흐름은 95/88 목표를 충족하지만, 실물 기기·실제 푸시·실제 결제·물리 기기 간 동기화는 별도 승인 없이 “완료”라고 부르면 안 된다.
