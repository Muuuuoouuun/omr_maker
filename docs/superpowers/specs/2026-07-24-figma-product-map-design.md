# OMR Maker Figma 제품 맵 설계

## 목적

현재 구현된 웹/PWA/Android 셸을 한 파일에서 탐색할 수 있도록 정보구조, 주요 화면,
사용자 흐름, 디자인 시스템을 Figma에 정리한다. 결과물은 새 UI를 발명하는 시안이 아니라
현재 코드의 구조와 화면을 설계·개발·리뷰에 다시 사용할 수 있는 제품 문서다.

## 검토한 접근

1. **화면 캡처만 수집**
   - 장점: 실제 화면과 가장 빠르게 일치한다.
   - 단점: 컴포넌트와 흐름을 재사용하거나 수정하기 어렵다.
2. **모든 화면을 편집 가능한 벡터로 재구성**
   - 장점: 이후 디자인 작업에 가장 유연하다.
   - 단점: 전체 라우트를 한 번에 재구성하면 비용이 크고 실제 구현과 쉽게 어긋난다.
3. **하이브리드 제품 맵 — 채택**
   - 실제 화면 인벤토리와 구조 다이어그램을 우선 만들고, 핵심 대표 화면과 공통
     컴포넌트만 편집 가능한 프레임으로 구성한다.
   - 현재 상태를 정확히 기록하면서 이후 리디자인의 출발점으로도 사용할 수 있다.

## Figma 파일 구조

### 00 Overview

- 제품 요약과 교사·학생 역할
- 전체 라우트 맵
- 웹, PWA, Android 셸의 관계
- 화면 상태 범례: 기본, 로딩, 빈 상태, 오류, 완료, 잠금

### 01 Screen Inventory

화면을 사용자 역할과 기능 영역으로 묶는다.

- 공용: 홈, 시험 생성, 그룹, PWA 점검
- 교사: 대시보드, 시험 상세, 실시간 현황, 응시 결과, 학생 관리, 결제, 설정
- 학생: 대시보드, 응시, 이력, 결과 리뷰와 재시험
- 반응형 기준: 데스크톱 1440px, 모바일 390px

각 프레임 이름에는 코드 라우트를 포함한다. 데이터가 필요한 동적 화면은 대표 상태와
빈 상태를 구분한다.

### 02 User Flows

- 교사: 시험 생성 → 배포 → 실시간 감독 → 채점/분석 → 학생별 피드백
- 학생: 입장 → 응시 → 제출 → 결과 리뷰 → 오답 재시험
- 운영: 로그인/세션 → 동기화 → 오류 복구

화살표에는 사용자의 행동을 적고, 분기에는 권한·PIN·기간·네트워크 조건을 표시한다.

### 03 Design System

- 색상: primary, success, warning, error, grade-red, retake와 surface 계열
- 타이포그래피: Pretendard 본문/한글, Geist 숫자·통계
- 타입, 라운드, 그림자, 모션 토큰
- 공통 패턴: 버튼, 입력, 카드, StatusPill, 통계 카드, 탭, 모달, 헤더
- 라이트·다크 모드와 모바일 변형

토큰은 `src/app/globals.css`와 `docs/design-system.md`를 기준으로 한다. 새 값을 임의로
추가하지 않는다.

## 화면 제작 원칙

- 전체 화면을 단순 스크린샷 모음으로 끝내지 않는다. 화면 이름, 라우트, 역할, 상태를
  항상 함께 표기한다.
- 대표 화면은 Auto Layout으로 구성해 편집 가능하게 만든다.
- 실제 이미지가 포함된 웹 화면은 실행 화면 캡처를 참고하되, 핵심 UI 구조는 별도
  편집 가능한 프레임으로 유지한다.
- 현재 구현과 다른 개선안은 이 파일에 섞지 않고 별도 “Future Concepts” 영역에서만 다룬다.
- Android는 별도 네이티브 UI가 아니라 Capacitor 웹뷰 셸이므로 웹/PWA 구조에 연결해 표시한다.

## 완료 기준

- 현재 16개 라우트가 모두 인벤토리에 매핑된다.
- 교사와 학생의 핵심 흐름이 시작부터 결과/재시험까지 연결된다.
- 주요 토큰과 공유 컴포넌트가 코드 출처와 함께 정리된다.
- 데스크톱과 모바일 대표 화면을 최소 1개씩 편집 가능한 형태로 제공한다.
- 파일을 처음 보는 사람이 5분 안에 제품 구조와 화면 위치를 찾을 수 있다.

## 범위 밖

- 전체 화면의 신규 리디자인
- 모든 상태의 픽셀 단위 재현
- Figma Code Connect 매핑
- Android 네이티브 전용 화면 설계
