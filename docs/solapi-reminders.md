# 솔라피 학습 알림

교사 계정 메뉴 → **학습 알림** (`/teacher/reminders`)에서 사용합니다.
반 지정 시험과 개별 학생 과제의 미제출자에게 마감 전·마감 후 안내를 보냅니다.
공개 시험은 수신 대상이 정해져 있지 않아 자동 발송에서 제외합니다.

## 서버 연결

1. 기존 마이그레이션에 이어 `supabase/migrations/202609100001_solapi_reminders.sql`을 적용합니다.
   운영 환경에서는 최신 `supabase/production-server-boundary.sql`도 적용합니다.
2. `SUPABASE_SERVICE_ROLE_KEY`와 기존 Supabase URL, 교사 세션 설정을 서버에 등록합니다.
3. 아래 값을 서버 환경변수에 등록합니다. 키를 브라우저 저장소나 `NEXT_PUBLIC_` 변수에 넣지 않습니다.

| 변수 | 값 |
| --- | --- |
| `OMR_REMINDER_MODE` | 기본 `dry_run` (기록만 생성), `live` (전송), `disabled` (작업 중지) |
| `OMR_REMINDER_ORGANIZATION_ID` | 발송할 교실의 실제 `organization_id`. 하나의 솔라피 계정을 한 교실에 연결 |
| `SOLAPI_API_KEY`, `SOLAPI_API_SECRET` | 솔라피 API 인증 값 |
| `SOLAPI_KAKAO_PF_ID` | 솔라피에 연결한 카카오 비즈니스 채널 ID |
| `SOLAPI_TEMPLATE_BEFORE_DEADLINE` | 승인된 마감 전 템플릿 ID |
| `SOLAPI_TEMPLATE_OVERDUE` | 승인된 미제출 템플릿 ID |
| `SOLAPI_SENDER_NUMBER` | 문자 발송용 사전 등록 번호. 숫자만 입력 |
| `SOLAPI_SMS_FALLBACK` | 기본 `0`, 카톡 실패 시 문자 대체는 `1` |
| `NEXT_PUBLIC_SHARE_BASE_URL` | 학생이 접속할 실제 HTTPS origin. 경로·쿼리 없이 입력 |
| `CRON_SECRET` | 최소 32바이트의 임의 비밀값 |

SMS만 사용하면 카카오 채널·템플릿은 없어도 됩니다. 문자는 URL을 포함하므로 LMS로 접수합니다.
알림톡 전용은 발신번호 없이도 설정할 수 있지만 문자 대체 발송은 사용할 수 없습니다.
‘설정 완료’는 환경변수 형식 확인입니다. 계정 잔액, 발신번호 등록, 템플릿 승인 여부를
솔라피 콘솔에서 확인해야 합니다. 이 구현은 다른 교실의 데이터나 키를 공유하지 않습니다.

## 카카오 템플릿

마감 전 본문:

```text
#{학생명}님, #{시험명} 제출 마감은 #{마감시간}입니다. 아직 제출하지 않았다면 문제를 풀고 제출해주세요.
#{링크}
```

마감 후 본문:

```text
#{학생명}님, #{시험명} 제출 마감(#{마감시간})이 지났지만 제출 내역이 확인되지 않습니다. 선생님께 확인해주세요.
#{링크}
```

변수 이름을 그대로 등록합니다. ‘문제 풀러 가기’ 웹링크 버튼을 원하면 승인 템플릿에
`#{링크}`를 URL로 등록합니다. API에서 임의 버튼을 덮어쓰지 않습니다.
카카오가 최종 승인한 본문에 맞춰 필요한 문구 수정을 반영한 뒤 활성화합니다.
전송 지연에도 문구가 틀리지 않도록 남은 분 수 대신 한국 시간의 정확한 마감을 안내합니다.
링크는 학생 풀이 화면으로 이어지고 기존 학생 로그인·배정 권한 검사를 그대로 거칩니다.

## 운영 순서

1. `dry_run`으로 배포합니다. 학생 명단을 서버에 저장하고 학습 알림에서 전화번호와 사용 여부를 저장합니다.
2. 시험을 선택해 마감 전 시간, 마감 후 시간, 정숙 시간을 설정하고 저장합니다.
   기본값은 마감 60분 전 / 마감 60분 후, 한국 시간 21시~08시 정숙입니다.
3. 대상 미리보기에서 이름·전화번호 끝자리·본문을 확인합니다. 연락처가 없거나 사용을 끈 학생은 제외됩니다.
4. 시험마다 자동 알림을 켭니다. 활성화 시 기존 Pro/Academy 권한 검사를 적용합니다.
5. 스케줄러가 실행된 뒤 ‘미리보기 기록’을 확인합니다.
6. 승인된 템플릿과 수신 대상을 검토한 뒤 서버에서 `OMR_REMINDER_MODE=live`로 바꾸고 재배포합니다.
   이 변경 이후 활성화된 모든 시험에서 실제 발송이 시작되고 비용이 발생합니다.
   배포/실제 발송 활성화는 이번 소스 구현 작업만으로 실행되지 않습니다.

## 스케줄러와 접수 결과

`vercel.json`은 `/api/internal/reminders`를 5분마다 호출합니다. 이 주기를 지원하는
호스팅 플랜이 필요합니다. Vercel 외 스케줄러에서는 같은 HTTPS 경로를 호출하면서
`Authorization: Bearer <CRON_SECRET>`을 전달합니다. GET이 실제 작업을 실행하므로
운영 점검 중 임의로 호출하지 않습니다. 키가 없거나 짧으면 401로 거부합니다.

작업은 요청마다 최대 25건, 약 40초 예산으로 처리합니다. 밀린 작업은 다음 실행에서 이어갑니다.
따라서 분·초 단위 도착을 보장하는 시험 타이머 대용으로 사용하지 않습니다.
정숙 시간의 사전 알림은 마감 전까지만 대기하고, 미제출 알림은 설정 시각부터 24시간까지만 대기합니다.
이미 마감된 과거 시험을 한꺼번에 독촉하지 않습니다. 개별 과제는 과제 마감과 배정 버전을 사용합니다.

서버는 발송 직전 제출 상태와 활성 배정을 다시 읽습니다. 시험·학생·과제 버전·마감·알림 종류별
DB 고유키로 중복을 차단합니다. 미리보기와 실제 발송 기록은 별도로 계산합니다.
설정을 저장한 교사의 권한/세션이 취소되거나 플랜이 내려가면 자동 발송도 중단됩니다.
중단된 시험은 자동 알림 사용이 꺼집니다. 교사가 다시 로그인해 해당 시험의 자동 알림을 켜고
설정을 저장하면 새 권한으로 재개합니다.

‘솔라피 접수’는 API가 요청을 수락했다는 뜻이며 수신 완료가 아닙니다. 최종 결과는 솔라피
콘솔의 접수번호로 확인합니다. 4xx/등록 거절은 ‘접수 실패’, 타임아웃·5xx·응답 파싱 오류는
‘결과 확인 필요’입니다. 이들은 자동 재전송하지 않습니다. 요청 후 작업이 중단되면 다음
스케줄러 실행에서 2분 이상 된 ‘접수 확인 중’ 기록을 ‘결과 확인 필요’로 전환합니다.
DB 접수 이후 학생이 제출하는 극히 짧은 구간까지 외부 메시지를 취소할 수는 없습니다.

전화번호 전체는 서버 연락처 테이블에만 저장합니다. 이력에는 끝 네 자리만 저장하고
실패 응답 본문·API 키는 로그에 남기지 않습니다. 학생 삭제 시 연락처와 이력도 삭제됩니다.

## 검증

`npm test -- src/lib/solapiProvider.server.test.ts src/lib/solapiReminderWorker.server.test.ts`
및 `npm run test:supabase:live`로 모의 API/로컬 PostgreSQL을 검증합니다. 실제 솔라피로 보내는 테스트는 없습니다.
